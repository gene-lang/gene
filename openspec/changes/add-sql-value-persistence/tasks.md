## 3. Gene API Surface

- [ ] 3.1 Implement `src/genex/db_store.nim` exposing `open`, `put`, `get`, `has?`, `delete`, `scan`, `close`, plus the namespace export wired through `gene_init`. Orphan blob cleanup is internal to `delete`/`put`; there is no user-callable `gc_blobs` in v1.
- [ ] 3.2 `open` accepts an existing `SQLiteConnection|PostgresConnection|MySQLConnection` *or* a `(^backend "sqlite" ^dsn ...)` shorthand that opens the connection internally.
- [ ] 3.3 `put` writes the encoded payload to `gene_values.inline_payload` always — no size routing, no threshold check. When `^externalize` is set, additional rows are written to `gene_blobs` and `gene_value_blobs` per Section 8.
- [ ] 3.4 `scan` returns an eagerly-iterated sequence (Gene-level) of `(id, value)` pairs keyed by id prefix, ordered by id. Each returned value is fully materialized at the root; any externalized children inside it are `VkLazyDbValue` wrappers (see Section 5), so the eager pass touches only `gene_values` (plus one batched `gene_value_blobs` SELECT per id that has externalized children).
- [ ] 3.5 Implement automatic orphan blob cleanup inside `delete` and `put` for externalized children only. `put` without `^externalize` MUST NOT issue any orphan-cleanup statement. `delete` of an id with no `gene_value_blobs` rows MUST NOT issue any orphan-cleanup statement either. When `^externalize` is in play, capture the previously-mapped `(child_path, blob_sha256)` rows via the portable mechanism appropriate to the dialect — a single prepared CTE that reads `gene_value_blobs` and performs the new mapping upserts on SQLite 3.35+ and Postgres; an explicit `SELECT child_path, blob_sha256 FROM gene_value_blobs WHERE value_id = ? FOR UPDATE` inside the same transaction on MySQL 8.0. Then conditionally `DELETE FROM gene_blobs WHERE sha256 = ? AND NOT EXISTS (SELECT 1 FROM gene_value_blobs WHERE blob_sha256 = ?)` in the same transaction for each evicted hash. On the `delete` side use `DELETE ... RETURNING blob_sha256` on SQLite 3.35+/Postgres and a prior `SELECT ... FOR UPDATE` on MySQL.

## 4. Fast-Update Path

- [ ] 4.1 Build a per-connection prepared-statement cache keyed by `(dialect, stmt_kind)`; prepare UPSERT, GET, DELETE, HAS, SCAN once at first use and re-bind thereafter.
- [ ] 4.2 Implement single-statement UPSERT for SQLite (`INSERT INTO gene_values(id, kind, inline_format, inline_payload, byte_size, updated_at) VALUES(?, ...) ON CONFLICT(id) DO UPDATE SET inline_payload=excluded.inline_payload, kind=excluded.kind, inline_format=excluded.inline_format, byte_size=excluded.byte_size, updated_at=excluded.updated_at`), Postgres (`ON CONFLICT (id) DO UPDATE`), and MySQL (`ON DUPLICATE KEY UPDATE`). No `blob_sha256` column in the column list — the v1 `gene_values` schema does not have one.
- [ ] 4.3 Implement idempotent child-blob upsert (used by Section 8 externalize path): `INSERT OR IGNORE INTO gene_blobs ...` (SQLite), `ON CONFLICT (sha256) DO NOTHING` (Postgres), `INSERT IGNORE` (MySQL) — no `SELECT` first.
- [ ] 4.4 The `put` fast path (no `^externalize`) executes exactly one prepared UPSERT, no transaction wrap, no prior-hash capture, no `gene_blobs` or `gene_value_blobs` touch. The externalize path is covered by Section 8 (one transaction containing: prior-mapping read + child blob upserts + child mapping upserts + root UPSERT + conditional orphan-cleanup DELETEs).
- [ ] 4.5 The codec hashes externalized children only; it never hashes the root payload. (Removed: prior task to "skip SHA-256 when below inline_threshold" — v1 has no inline_threshold and no root hash.)
- [ ] 4.6 Add a perf test under `tests/perf/test_db_store_perf.nim` asserting that a `put` without `^externalize` against an in-memory SQLite store issues exactly one prepared statement (verified via a query counter), that a `delete` of an id with no externalized children issues exactly one, and that the prepared statements are re-used across iterations.

Reserve a reference-cell payload carrying `(store_handle, value_id, child_path, blob_sha256, inline_format, original_kind, byte_size)`. v1 uses the wrapper only for externalized children, so `child_path` is always non-empty.
- [ ] 5.2 Implement `materialize_lazy_db(value)` in `src/genex/db_store.nim`: issue `SELECT inline_data FROM gene_blobs WHERE sha256 = ?` (v1 omits `external_uri`), decode via the codec, atomically replace the wrapper's reference cell with the resolved value; idempotent on repeated calls.
- [ ] 5.3 Extend `kind()` in `src/gene/types/core/value_ops.nim` (around line 638, in the `REF_TAG` branch) with a single case: when `v.ref.kind == VkLazyDbValue`, return the cached `original_kind` instead of `VkLazyDbValue`. This is the only edit to the type-introspection hot path; all other `case v.kind` callers see the original kind.
- [ ] 5.4 Upgrade structural accessors that today are inline templates over the NaN-box tag (`array_data` / `map_data` at `src/gene/types/core/value_ops.nim:95-160`, plus the `gene_*` field-read templates) so that a `VkLazyDbValue` argument calls `materialize_lazy_db` first and then re-binds through the materialized value's tag. The hot non-lazy path remains a single tag check.
- [ ] 5.5 Short-circuit equality between two `VkLazyDbValue`s with the same `(store_handle, blob_sha256)` to `true` without materializing either side, mirroring the existing `VkCustom` short-circuit at `value_ops.nim:431-436`.
- [ ] 5.6 Ensure serialization of a `VkLazyDbValue` (e.g., it is the input to another `put`) materializes first so on-disk payloads never contain lazy markers.
- [ ] 5.7 Make `get` always return a fully materialized root value. Wrappers MUST appear only at externalized child paths inside the returned value; a `put` without `^externalize` MUST round-trip with no wrappers anywhere in the result.
- [ ] 5.8 Expose `(genex/db_store/materialize v)` as an explicit escape hatch that forces resolution of any `VkLazyDbValue` reached as an externalized field child, without touching unrelated values.
- [ ] 5.9 Add `tests/test_db_store_lazy.nim` covering: (a) `get` of a value written with `^externalize` issues zero `gene_blobs` queries until a wrapped child is accessed (one batched `gene_value_blobs` SELECT is allowed at `get` time to discover the mappings), (b) first content access on a wrapped child issues exactly one query and the wrapper is replaced, (c) repeated access after the first issues zero further queries, (d) `get` of a value written without `^externalize` returns a fully materialized value with no wrappers anywhere and no `gene_value_blobs` query, (e) Gene-level `kind` introspection on a wrapped child reports the original kind, (f) explicit `materialize` is a no-op on already-materialized values and idempotent on repeated calls.

## 8. Field-Level Externalization

- [ ] 8.1 Add a `gene_value_blobs(value_id, child_path, blob_sha256)` mapping table to the DDL templates in `src/genex/db_store/schema.nim` for all three dialects: primary key `(value_id, child_path)`, secondary index on `blob_sha256` to support orphan-check, and an `ON DELETE CASCADE`-equivalent cleanup driven by the store (no FK to `gene_values` so the dialects stay consistent; cleanup is application-side inside the same transaction as `delete`/`put`).
- [ ] 8.2 Extract the `^externalize` selector parser and validator from `src/gene/serdes.nim:1125-1217` into a shared helper reachable from both serdes and `db_store`. The current parser is tightly coupled to `filesystem_write_error` (raises a filesystem-shaped error string at `serdes.nim:1155, 1161, 1169, 1173, 1180, 1184, 1204, 1211`); the refactor MUST replace the inline error sink with a caller-supplied error callback (or a typed `Result`) so the same parser can produce SQL-shaped error messages for `db_store` and filesystem-shaped ones for serdes. Validation rules MUST remain identical: enforce absolute selectors (`/path`), reject root selectors, reject empty segments, reject wildcards (`*`, `**`, `@`, `@@`, `!`), reject duplicates, and reject ancestor/descendant overlap.
- [ ] 8.3 Extend `src/genex/db_store/codec.nim` with a `encode_with_externalize(value, selectors)` entry point that returns `(parent_payload, child_payloads: seq[(child_path, payload, sha256, byte_size)])`; the parent payload places a stable placeholder marker at each externalized path so the decoder can re-install a `VkLazyDbValue` there.
- [ ] 8.4 In `src/genex/db_store.nim::put`, when `^externalize` is set: encode parent + children, upsert each `gene_blobs` row by sha256 (idempotent), upsert each `gene_value_blobs(value_id, child_path, blob_sha256)` row, upsert the root `gene_values` row, then run a single orphan-cleanup pass that deletes from `gene_blobs` any child sha256 that the operation evicted and which no `gene_value_blobs` row still references — all inside one transaction. (v1 has no `gene_values.blob_sha256` column, so the orphan-check predicate is single-table.)
- [ ] 8.5 In `delete`, also remove every `gene_value_blobs` row for the target `value_id` and orphan-check each evicted blob sha256 against `gene_value_blobs.blob_sha256` only. (v1 has no root-level referrer.)
- [ ] 8.6 `VkLazyDbValue`'s payload (defined in 5.1) is the per-child descriptor used by `^externalize`. `materialize_lazy_db` resolves via `SELECT inline_data FROM gene_blobs WHERE sha256 = ?` — the sha256 is captured at `get` time so materialization does not re-hit `gene_value_blobs`.
- [ ] 8.7 In `get`, after decoding the parent payload, walk the decoded value and replace each placeholder marker with a `VkLazyDbValue` populated from the corresponding `gene_value_blobs` row (one batched `SELECT child_path, blob_sha256 ... - [ ] 8.8 Add `tests/test_db_store_externalize.nim` covering: (a) selector validation matches `serdes.nim` (absolute, no root, no wildcards, no duplicates, no overlap), (b) a `put` with `^externalize [/avatar]` writes exactly one `gene_value_blobs` row and one `gene_blobs` row for the avatar regardless of avatar size, (c) the root parent payload itself is inline when the residual is small, (d) `get` returns a `VkLazyDbValue` at the externalized path and does not fetch the blob until first access, (e) replacing the value with one whose `/avatar` payload differs reclaims the old blob via orphan-check, (f) `delete` cascades to `gene_value_blobs` and orphan-cleans every previously-referenced blob, (g) two distinct ids with `^externalize` selectors hitting byte-identical sub-tree content share a single `gene_blobs` row.
